## Website event flow

Frontend event bridge: `main.js` exposes `window.repairAsapTrackEvent(eventName, params)`, sends the event to GA4 through `gtag('event', ...)`, and mirrors the event name to Clarity with `clarity('event', ...)`. `/analytics.js` defines the analytics globals for all hosts, but it only loads external GA4/Clarity/Cloudflare Web Analytics network tags on production hostnames. As of 2026-07-05, GA4 and Clarity are loaded on separate schedules: GA4 is pulled earlier after load/idle to reduce short-session undercounting, while Clarity remains later unless the user interacts or a lead event needs the vendor queue. Cloudflare Web Analytics is loaded immediately after deferred script ordering settles, with a duplicate-beacon guard for the transition from Cloudflare automatic setup to manual setup. This prevents local `127.0.0.1` / localhost sessions and `crm.asap.repair` sessions from polluting production public-site analytics while keeping site JS safe in local previews and reducing homepage LCP/TBT pressure.
